## 阶段 6：分层图最短路径 SHORTEST_K

### 6.1 场景

每位学生有最多 K 张加速券（0 ≤ K ≤ 10），每张券可将一条边的步行时间从 `walk_time` 缩短为 `ceil(walk_time / 3)`（模拟骑行/接驳车，约 3 倍速）。每张券绑定一条边，不必用满。求最短到达时间、实际用券数、用券的边。

### 6.2 算法设计：K 层状态图 Dijkstra

#### 核心思想

将"已用券数"作为**额外状态维度**，把原图在逻辑上展开为 K+1 层：第 k 层表示"恰好用了 k 张券到达该节点"。

**状态定义**：`dist[place_id][k]` = 到达地点 `place_id`、恰好使用了 k 张券的最短步行时间。

**状态转移**（对每条 status=open 的边 u→v，walk_time = w）：

```
分支 1（不用券）：dist[v][k] = min(dist[v][k], dist[u][k] + w)
分支 2（用券，k+1 ≤ K）：dist[v][k+1] = min(dist[v][k+1], dist[u][k] + ceil(w/3))
```

#### 为什么 Dijkstra 仍然正确

扩展后的状态图中边权仍然非负（`w ≥ 0`，`ceil(w/3) ≥ 0`），所以 Dijkstra 的贪心性质不变——优先队列中第一次弹出某个 `(place_id, k)` 状态时，其距离就是最短的。

#### 关键反例：贪心算法为何失败

```
图: A —10min— B —10min— C —10min— D
    A ——5min—— X —50min—— D
```

K=1 时：
- **贪心做法**：先求普通最短路 A→B→C→D (30min)，然后在最长边上用券 → ceil(10/3)=4，总计 4+10+10=24min
- **分层图做法**：走 A→X→D，在 X→D 边用券 → 5+ceil(50/3)=5+17=**22min** ✓

贪心选错路径是因为"先确定路径再选边用券"忽略了路径选择与用券决策的耦合关系。分层图在每个状态里同时优化路径和用券决策。

### 6.3 具体实现细节

#### 数据结构

```cpp
// dist[v][k] — 双层 unordered_map，稀疏存储
std::unordered_map<std::string, std::unordered_map<int, int>> dist;

// 前驱追踪（分开存储比存 pair 更直观）
std::unordered_map<std::string, std::unordered_map<int, std::string>> prev_node;
std::unordered_map<std::string, std::unordered_map<int, int>> prev_k_map;
std::unordered_map<std::string, std::unordered_map<int, bool>> coupon;

// 优先队列元素：(time, place_id, k)，小顶堆
using PQEntry = std::tuple<int, std::string, int>;
std::priority_queue<PQEntry, std::vector<PQEntry>, std::greater<PQEntry>> pq;
```

#### 算法流程

1. **初始化**：`dist[from_id][0] = 0`，push `(0, from_id, 0)` 入队
2. **循环**：弹堆顶 `(time, u, k)`
   - 陈旧检测：`time != dist[u][k]` → 跳过
   - 终点检测：`u == to_id` → `break`（第一次弹出即最优解）
   - 遍历 u 的所有邻接边（仅 status=open）
     - **不用券**：`nd = time + w`，若能改进 `dist[v][k]` 则更新并入队
     - **用券**（若 k+1 ≤ K）：`nd = time + (w+2)/3`（整数除法上取整），若改进 `dist[v][k+1]` 则更新并入队
3. **不可达判断**：若循环结束仍未弹出来自 `to_id` 的状态 → 返回 `reachable=false`
4. **路径回溯**：从 `(to_id, best_k)` 出发，沿 `prev_node` 和 `prev_k_map` 反向溯源到 `(from_id, 0)`，每步检查 `coupon[curr][ck]` 决定是否记录用券边
5. **翻转并输出**：路径 reverse，用券边 reverse 后按 `(min(u,v), max(u,v))` 字典序排序

#### 复杂度

时间复杂度 O((K+1)·(V+E)·log(V·K))，K ≤ 10 时接近 O((V+E)·log V)。空间 O(V·K)。对 1000 节点规模完全可接受。

### 7.2 对抗样例

#### 对抗目标 1：TIMED_SHORTEST 中间节点时间窗口检查

**被卡住的错误实现**：只检查起点和终点在查询时刻是否开放，但不在 Dijkstra 松弛循环中对每个邻居节点做时间检查。

**对抗图构造**：

```
P0001(学生宿舍,全天) ——2min—— P0003(第二食堂,06:00-21:00) ——2min—— P0007(南门,全天)
P0001(学生宿舍,全天) ——8min—— P0006(体育场,06:00-22:00)   ——4min—— P0007(南门,全天)
```

- 短路径 P0001→P0003→P0007：总时间 **4 分钟**，但经过 P0003（食堂），21:00 后关闭
- 绕路 P0001→P0006→P0007：总时间 **12 分钟**，所有节点 22:00 仍开放

**测试命令**：`TIMED_SHORTEST P0001 P0007 22:00 TIME`

| 时刻 | 错误实现输出 | 正确输出 | 说明 |
|------|:--:|:--:|------|
| 12:00（食堂开着） | 4min | 4min | 两者一致 |
| **22:00（食堂关了）** | **4min** ✗ | **12min** ✓ | 错误实现未检查 P0003，穿过了已关闭节点 |

我程序的实测结果：`PATH TIME 12 NODES P0001 P0006 P0007`，正确绕开了已关闭的食堂。

#### 对抗目标 2：SHORTEST_K 贪心反例（主数据集配合）

主数据集 case_layered_01 已覆盖（A-B-C-D vs A-X-D）。对抗样例中 P0001→P0007 两条边（P0001-P0003 2min, P0003-P0007 2min），K=2 时两券齐用 → ceil(2/3)+ceil(2/3)=1+1=2min，比 K=1（ceil(2/3)+2=1+2=3min）更优。这验证了分层图 DP 而非贪心。

## 知识积累

### SHORTEST_K 分层图模式

将约束计数（已用券数）作为状态维度展开为多层图，每层内部正常 Dijkstra，层间通过"特殊转移"（用券降时间）连接。这种模式适用于任何"有 K 次特权可使用"的最短路变体。

### FAST 边排序陷阱

路径回溯给出的边顺序是路径遍历顺序（从起点到终点），但评测接口要求按 `(min(u,v), max(u,v))` 字典序输出。large 测试暴露此问题——两条边 P0216-P0419 和 P0216-P0559 在回溯顺序与字典序不同时出错。修复方式：输出前对 fast_edges 做 `std::sort`。

### 数据集设计原则

- **多重路径**：确保 SHORTEST 有选择空间（步行 vs 地铁）
- **差异化时间窗口**：测试 TIMED_SHORTEST 的时间过滤
- **拓扑特征**：河流/道路天然形成桥和割点，验证 CRITICAL
- **权值独立性**：distance 和 walk_time 不完全正相关（地铁边：距离不短但时间极短）

### 对抗样例设计原则

- 构造"看似最优但实则有隐藏约束"的场景
- 错误实现通常遗漏边界条件（中间节点时间、券数限制）
- 正确实现的输出应与错误实现的输出有**显著差异**（4 vs 12，而非 4 vs 5）
